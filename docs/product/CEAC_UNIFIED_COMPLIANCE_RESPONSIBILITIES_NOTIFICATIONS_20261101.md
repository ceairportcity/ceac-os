# CEAC OS — Unified responsibilities, Compliance reporting and notifications
Status: implementation plan for the authorised November 1 redesign. Preserve existing production data, permissions, app colours, navigation and current completed reporting/design work. This is an extension of CEAC OS, not a replacement.

## Product contract
- One account and one attendance history per person. Department memberships and assignments grant a **scope of work**, not a second identity or a second workday.
- Current department is a convenient filter/default, never the sole source of a person's authority or work history.
- Keep specialised Compliance and Technical Support workspaces as authorised navigation destinations, not separate sign-ins or duplicated dashboards.
- Record department on each responsibility, activity and project contribution. When someone such as Catherine or Frank contributes to several departments, show each contribution in its department, but count their attendance once.
- Attendance sessions, reported activity durations, reviewed work, approved leave and Compliance observations are different kinds of evidence. Do not equate them.
- Preserve Compliance's independence from HR, protected personnel records, executive decisions and payroll. Never automatically impose a penalty, wage deduction or employee score.
- Maintain clear everyday English. Use the existing CEAC palette, readable text, accessible interactions, compact views, drill-down detail, filtering, pagination and mobile layouts.

## Delivery sequence and dependencies
1. **Evidence foundation (first change)**: show compact, deduplicated factual daily attendance counts within the existing Compliance Overview using only the existing authorised attendance-day response. No new permissions or backend writes. Include tests for multiple memberships, unscheduled days, leave and open sessions. It must never label missing login a violation.
2. **Responsibility-first workspace**: inspect every place where changing current unit changes the entire role/panel. Reuse authorised memberships and grants across navigation and work forms; present an optional department filter inside Work, Projects, Team and Reports. Retain a unit selection only where it describes the current action. Do not widen database access. Keep specialised Compliance and IT Support tabs behind their existing grants. Confirm managers' cross-department reviewer routes and avoid making HR every manager's default reviewer.
3. **Attendance and contribution record**: preserve a single personal start/end session (office/home) and record dated activities against their specific authorised departments. Treat open/overnight sessions as questions for review, not proven continuous hours. Reconcile schedules, approved leave, attendance corrections and temporary permissions before determining a missing record. Never sum duplicate attendance across units.
4. **Secure weekly/monthly Compliance evidence service**: implement a date-range server query that returns authorised, paginated roster-day facts, with a fixed Ghana reporting calendar. The query must use the same scoped evidence rules as the existing attendance-day RPC; no client-side 30-day fan-out and no public raw location stream. Include scheduled days, starts/ends, recorded location category, leave, permissions, changes/corrections, overnight sessions, and review status. Where evidence is unavailable say “Not verified”; never silently show zero. Human review remains required for lateness or breaches.
5. **Compliance UI**: five main sections: Overview, Attendance (day/week/month), Reviews (attendance cases, evidence, exceptions), Policies (requirements, revisions, acknowledgements), Reports (individual, departmental, whole-organisation). Add search, role-scoped department/person filters, manageable pages, clear status and source-linked detail drawers. Retain the map as an optional compact evidence view. Design desktop and phone layouts without long walls of cards.
6. **Issued monthly reports**: Catherine reviews period records, staff explanations and confirmed observations, then issues an immutable report version. Keep individual report and organisation summary separate; show which people and dates were covered, source provenance, unresolved matters, corrections issued later and who approved what. HR gets authorised administrative tasks. Group Pastor receives the relevant leadership summary/decision requests. Payroll stays separate, with independent lawful HR review and no automatic financial action.
7. **One notification centre**: build on existing work-attention state and Memos rather than create another chat service. Durable events for observation opened, staff response, referral, evidence or exception, policy update/acknowledgement, report submitted, cross-department assignment and executive request. Route to the exact authorised recipient at event time; use stable event/recipient keys to prevent duplicates and allow read/acted-on status. Display “Needs your attention” and “Updates” with record deep-links, sensible grouping and quiet previews. No sensitive case text in notifications. No auto-created Memo. Handle role changes without exposing old sensitive links.
8. **Connected reports**: improve HR, Manager and Executive reports using the same verified sources. Show department work contribution without multiplying personal attendance. Executive gets concise trends, human-reviewed exceptions and decisions, not all work entries. Respect role-based report visibility and fixed issued snapshots.
9. **Release checks**: unit tests for date/deduplication/routing, scoped server/RLS tests including cross-tenant and multi-role denial, browser journeys for Catherine/Frank/HR/Executive/staff, mobile/tablet screenshots, export/snapshot reconciliation, CI and preview verification. Only then merge and deploy; do not modify production during drafting.

## Acceptance examples
- Catherine starts work once, works on Compliance and Children's Ministry items, sees both contributions; neither department report adds a second attendance day.
- Frank sees his assigned Media and other department work without switching the whole application. He can act only with his real permissions.
- A scheduled person who did not record a start appears as **No start recorded**, with leave/permissions visible; no automatic misconduct finding.
- A session that crosses midnight is attributed correctly, marked for review where required, and never counted as uninterrupted verified work.
- One Compliance observation triggers one staff action notification. A response notifies the assigned Compliance reviewer, referral notifies only authorised HR, and an executive request notifies only the Group Pastor/designated executive.
- Weekly totals reconcile to underlying daily evidence; monthly summaries reconcile to weekly/daily values without duplicated people or hours. Submitted reports cannot change silently.
- Nobody sees another person's restricted record through a deep-link, notification, saved report or department filter.
