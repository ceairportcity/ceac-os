# CEAC OS — Operational Clarity Acceptance Contract

Status: **BINDING**

This contract prevents the approved product direction from turning into a materially different implementation.

## Visual authority

Primary in-repo reference:

`docs/operational-clarity/reference/APPROVED_REFERENCE.html`

The reference controls:
- information hierarchy;
- component density;
- composer/drawer model;
- placement of primary actions;
- Executive overview structure;
- Create menu structure;
- Room file/media treatment;
- global-search grouping pattern.

Illustrative counts, names, dates and sample values are **not** data requirements.

No fake product data may be created to make a screenshot resemble the reference.

# Composer acceptance

## Work Item Composer

Must:
- replace the long form;
- use the right-side drawer on desktop;
- use full-screen composer on mobile;
- keep required fields prominent;
- expose attachments and subtasks without excessive scrolling;
- keep Instructions and Finished result compact until needed;
- preserve all Work Engine authority;
- distinguish assignment attachments from submission/evidence.

Must not:
- restore seven large work-type cards as the default body;
- fake Priority or Progress;
- hide essential assignment fields behind multiple wizard steps.

## Ministry composer

Must:
- use plain-language headings;
- keep measurement detail conditional;
- preserve revision/audit semantics;
- avoid exposing internal strategy-record language as the primary experience.

## Announcement composer

Must:
- be reachable from Create and Announcements;
- support authoritative audiences;
- support attachments once Files foundation exists.

# Executive acceptance

The Executive overview must make `Needs your attention` the dominant first operational block.

A new user should be able to answer within seconds:
- what needs the Group Pastor;
- what is at risk / blocked / awaiting decision;
- where ministry direction stands;
- where to drill in.

System disclaimers must not dominate card titles or the first reading path.

Portfolio and Organisation must operate at Executive altitude by default.

---

# Communication acceptance

The Executive:
- can discover every active Unit Room;
- can discover every active Sub-team Room;
- can enter and communicate in those rooms;
- is not granted unrestricted private staff DMs.

The Executive Messages home must not simply preload all organisational conversations as an unread firehose.

Announcement creation must not depend on discovering a hidden Room action.

---

# Files and media acceptance

Operational work files must be private.

Protected HR remains isolated.

At minimum, prove:
- unauthorised profile cannot open another context's file;
- authorised profile can open/download;
- deleted/replaced permissions do not leave a public URL;
- Work source attachment is not mislabelled as employee submission evidence;
- same underlying file can be referenced contextually without unnecessary binary duplication.

No permanent public bucket for ordinary CEAC operational files.

---

# Search acceptance

The top search must no longer be a destination-only filter.

It must return authorised grouped results.

Required acceptance probes:
- `announcement` returns appropriate action/destination/records;
- project search;
- work search;
- person search;
- department/sub-team search;
- uploaded filename search.

Protected HR and unauthorised project/work/file data must not leak through labels, snippets, counts or autocomplete.

Search empty state must clearly state that there are no matching authorised results.

---

# Responsive acceptance

Mobile is not accepted if:
- desktop columns simply stack into a long page;
- critical action moves several screens below the content;
- metadata controls become oversized;
- drawers are squeezed into a narrow right rail.

Composer becomes full-screen on mobile.

Global search becomes a mobile-appropriate search sheet/surface.

Room attachments remain readable and tappable.

---

# Screenshot rule

For each visual family, capture the implemented surface at the agreed viewport and compare side-by-side with the approved reference.

Acceptance language must be literal:
- not “premium”;
- not “same feel”;
- not “close enough”;
- not “same principles.”

Record the actual mismatches and correct them unless the mismatch is required by truthful CEAC data or a protected authority contract.
