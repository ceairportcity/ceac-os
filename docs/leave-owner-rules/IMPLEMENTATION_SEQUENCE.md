# Leave Owner Rules — Staged Sequence

## LOR0 — Lock owner decisions
Record the confirmed leave categories and approval flow, and explicitly preserve unresolved mathematics as unconfigured.

## LOR1 — Server/domain enforcement
Persist the confirmed routing subset without activating invented entitlements. Requests must accept only confirmed leave categories. Manager cannot final-approve manager-then-Administration leave.

## LOR2 — Employee UI
Expose exactly the confirmed request categories in My Hub: Annual, Sick, Maternity, Paternity and Study. Historical unsupported kinds remain readable but cannot be newly requested.

## LOR3 — Acceptance contracts
Prove five confirmed categories, no arbitrary "Other" request, Manager escalation, Administration final approval, and no implicit entitlement/carry-over activation.

## LOR4 — Production closure
Merge through protected main, apply the migration, verify categories/routing in production, and confirm numeric leave policy remains explicitly unconfigured until owner values are supplied.
