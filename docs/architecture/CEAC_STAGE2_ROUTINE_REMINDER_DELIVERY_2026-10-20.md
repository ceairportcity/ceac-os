# Routine reminder delivery — existing Work/attention engine

169/170 extend the existing five-minute heartbeat and CEAC Messages. It creates no provider, external email/push/chat transmission, second scheduler, private Calendar task or completion decision. Reminders are opt-in (off for every existing routine), 0–1440 minutes before the version's real IANA due instant. Creation and future version changes retain their exact existing authority.

The canonical schedule calculation is factored unchanged into a private STABLE invoker reader with the same bounds/source RLS. Authenticated direct calls additionally require their active organisation and future assurance. Public preview retains its existing authentication boundary and signature. The private trusted delivery worker has no PUBLIC/anon/authenticated/service execution grant; the existing service-only heartbeat calls it as owner. The public authenticated privileged-signature inventory remains148; the new private worker and invoker helper are separately reviewed in security tests.

At most200 configured operations are swept per heartbeat, with transactional cursor progress and advisory locking. Preview remains bounded to five dates around the current Accra day; due instants still use each actual schedule timezone, interval, count, dated version, pause history and recorded proof. Eligible reminder time must have arrived and due must be within the last24 hours. Failed execution rolls back cursor/delivery and is visible as an actual failed cron run, not a fabricated successful job. Larger estates rotate through batches; no five-minute SLA is claimed for more than200 configured operations.

Delivery requires the current active assignee, active unit and recorded unit membership; an effective workforce pattern/day type and explicit working hours; a working day/time in the organisation's Accra clock; no approved leave. An explicit day-specific override, including blank hours, takes precedence over general hours. Missing patterns/hours, non-working days, closed hours, paused/off/completed/cancelled or recorded routines produce no delivery. This does not determine attendance or change HR records. Special quiet cutoffs separate from a recorded workforce end time are not newly implemented here.

One immutable, audited receipt per operation/date/recipient survives retries and offline use. Receipt RLS is recipient-only, subject to current visible Work/assignee, organisation and assurance. A former assignee cannot retain access after reassignment. Direct client receipt writes and worker execution are denied. Existing Messages/Needs action reads the receipt through the existing invoker attention queue and current canonical date. A real recorded outcome clears its action; the receipt and parent Work status remain unchanged. No inferred human review, completion, score, automatic follow-up or escalation.

Messages labels the action Routine due rather than New assignment and distinguishes delivered reminders from unread communication. Scoped request cancellation and focus refresh prevent old account/unit reads from restoring previous content.
